# راهبرد تست

تست هر قابلیت همراه همان بخش نوشته و اجرا می‌شود. تستی که اجرا نشده موفق گزارش نمی‌شود. کامپایل شدن به‌تنهایی سلامت نیست.

## ابزار

| لایه | ابزار | از بخش |
| --- | --- | --- |
| موتور و API پایتون | pytest و TestClient فست‌ای‌پی‌آی | ۱ |
| قرارداد شمارش و پول | pytest با `Decimal` | ۳ به بعد |
| رابط | آزمون واحد اجزا، و مرورگر برای جریان اصلی | ۱ برای پوسته، ۶ به بعد برای جریان کامل |
| فایل واقعی | فایل ساخته‌شده در fixture با openpyxl و csv و در صورت نیاز یک xls کوچک | ۲ |

دستورهای پیش‌بینی‌شده، بعد از وجود کد:

```text
cd apps/api && python -m pytest
cd apps/web && npm test
```

در بخش صفر این دستورها اجرا نمی‌شوند چون هنوز پروژه‌ای وجود ندارد.

فیکسچر در مخزن، فایل کاربر واقعی نیست. تست‌ها فایل را در پوشه موقت می‌سازند، عملیات را اجرا می‌کنند، و خروجی را با کتابخانه دوباره باز می‌کنند. نتیجه مورد انتظار در کد تست نوشته می‌شود، نه این‌که فقط «بدون استثنا تمام شد» کافی باشد.

## سطوح

**واحد:** نرمال‌سازی، تجزیه عدد و تاریخ، انتخاب کلید، هویت شمارش، اعتبارسنجی برنامه، پیام خطا.

**یکپارچگی:** API به همراه SQLite موقت و دیسک موقت؛ بارگذاری تا نسخه؛ اجرای ابزار تا فایل خروجی.

**رابط:** بارگذاری، دیدن نام فارسی، خطای قابل‌فهم، شروع عملیات، دیدن پیشرفت، دانلود. در هر بخش رابط که ظاهر عوض می‌شود، عرض ۳۶۰ و ۱۲۸۰ بررسی می‌شود. جهت محاسبه‌شده صفحه `rtl` است و فونت اعمال‌شده وزیرمتن است.

**انتهابه‌انتها:** از بخش چهار به بعد حداقل یک جریان کامل از فایل تا بازخوانی خروجی. در بخش یازده جریان مغایرت مالی سند مادر اجباری است.

**رگرسیون:** پس از هر بخش، مجموعه pytest موجود دوباره اجرا می‌شود. شکستن تست قبلی یعنی بخش تمام نشده است.

## فارسی

این رشته‌ها در تست‌های مرتبط، از بخش یک به بعد، استفاده می‌شوند. انتظار این است که ترتیب منطقی نویسه‌ها دست نخورد.

| مورد | نمونه |
| --- | --- |
| جمله ساده | `سلام، این یک متن فارسی معمولی است.` |
| ترکیب فارسی و انگلیسی | `فروش شعبه تهران در مهر برابر با 12500000 ریال (IRR) بود.` |
| رقم فارسی | `۱۲۳۴۵۶` |
| ی و ک عربی | `علي كريمي` که پس از قاعده پاک‌سازی به `علی کریمی` تبدیل می‌شود و پیش از آن دست نمی‌خورد |
| نیم‌فاصله | `علی‌رضا` باید پس از پاک‌سازی فاصله‌ها همچنان U+200C داشته باشد |
| تلفن | `09121234567` |
| شناسه با صفر | `0012345678` |
| ایمیل در جمله | `پاسخ را به user@example.com بفرستید.` |
| درصد و واحد | `رشد ۱۲٫۵٪ نسبت به مهر` |
| تاریخ شمسی | `۱۴۰۳/۰۷/۲۱` |
| تاریخ میلادی | `2024-10-12` |
| تاریخ مبهم | `02/03/04` که نباید بی‌صدا تبدیل شود |
| متن بلند | یک پاراگراف چندجمله‌ای فارسی در سلول و در پیام خطا |
| عنوان ستون | `نام مشتری`، `مبلغ فروش (ریال)`، `درصد اختلاف` |

تست فایل فارسی این‌ها را اثبات می‌کند:

- بازخوانی سلول xlsx با openpyxl برابر رشته نوشته‌شده باشد.
- `sheet_view.rightToLeft` برقرار باشد.
- csv نوشته‌شده با `utf-8-sig` باز شود و اولین سلول فارسی درست باشد.
- نام برگه فارسی در کتاب کار بماند.

تست رابط فارسی این‌ها را اثبات می‌کند:

- `document.documentElement.lang` برابر `fa` و `dir` برابر `rtl`.
- یک جمله نمونه در صفحه معکوس یا حرف‌به‌حرف جدا دیده نشود؛ متن DOM همان رشته منطقی باشد.
- ایمیل نمونه داخل عنصر `dir="ltr"` باشد.

معکوس کردن رشته برای «درست شدن» نمایش، خودش شکست تست است.

داده این فایل‌ها ساختگی و متعلق به شخص واقعی نیست. کد ملی نمونه یا ۱۰ صفر است یا با الگوریتم رقم کنترلی ساخته می‌شود و در تست به‌عنوان سند هویت واقعی استفاده نمی‌شود.

## امنیت و مرز

- درخواست فایل با فضای کار اشتباه: ۴۰۳ یا ۴۰۴، بدون بدنه فایل.
- آرشیو xlsx که اندازه غیرفشرده اعلامی‌اش بالای سقف است: `file.unsafe_archive` پیش از گسترش کامل.
- سلول ورودی با متن `=cmd|'/c calc'!A0` در مسیر csv خروجی خنثی شود و در xlsx به‌صورت فرمول اجراشدنی ذخیره نشود.
- برنامه JSON که ابزار `shell` دارد رد شود.
- لاگ تست بررسی کند مقدار یک سلول محرمانه نمونه در متن خطای API نیست. این کار با یک مقدار ساختگی یکتا انجام می‌شود.

## وابستگی خارجی در تست

| وابستگی | اگر نباشد |
| --- | --- |
| مدل زبانی | تست‌های پذیرش روی برنامه‌ریز قاعده‌مند اجرا می‌شوند. سناریوی اتصال مدل بدون متغیر محیط اجرا نمی‌شود و در گزارش با وضعیت «اجرا نشده به علت وابستگی» می‌آید. این وضعیت شکست تست‌های قاعده‌مند نیست. |
| LibreOffice | ارزیابی فرمول زنده اجرا نشده به علت وابستگی است. محاسبه پایتون باید مستقل از آن سبز باشد. |

## جمله‌های معیار برنامه‌ریز

این جمله‌ها باید، وقتی ابزارشان وارد رجیستری شد، بدون مدل زبانی به همان ابزار برسند:

| جمله | ابزار | بخش آزمون |
| --- | --- | --- |
| فروش بیشتر از ۵۰ میلیون را پیدا کن | `filter` | ۵ |
| داده‌ها را بر اساس مبلغ مرتب کن | `sort` | ۵ |
| ستون درصد اختلاف را اضافه کن | `compute_column` | ۵ |
| این دو فایل را تطبیق بده، اختلاف مبالغ را پیدا کن و فایل مغایرت بده | `reconcile` | ۵ و ۶ |
| بیشترین فروش متعلق به کدام شهر است | `rank` | ۷ |
| یک گزارش مدیریتی بساز | `report` | ۷ |
| روند فروش ماهانه را نشان بده | `trend` و `chart` | ۸ |
| یک داشبورد فروش بساز | `dashboard` | ۸ |
| دو برگه را با هم ادغام کن | `sheet_merge` | ۹ |
| یک فایل مدیریت فروش با برگه‌های فروش، مشتریان، محصولات، گزارش و داشبورد بساز | `create_workbook` | ۹ |
| همین گزارش را برای مهر هم بساز | برنامه قبلی با دوره جدید، یا یک سؤال اگر زمینه نباشد | ۶ |

جمله‌ای که به هیچ ابزاری نخورد باید `plan.ambiguous` با یک سؤال باشد، نه اجرای حدسی.

## تعریف شکست بخش

بخش تمام‌شده نیست اگر:

- تستی که خودش اضافه کرده قرمز باشد و بدون اصلاح رها شود؛
- تست قبلی مرتبط قرمز شود؛
- قابلیت بخش فقط با داده ثابتِ نمایشی کار کند؛
- فارسی نمونه در خروجی همان بخش ناخوانا باشد؛
- پیام موفقیت در سناریوی شکست ظاهر شود.
